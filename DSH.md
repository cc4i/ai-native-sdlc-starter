# DeepSeek Harness Directives (DSH.md)

This file provides system instructions, conventions, and operational workflows for **DeepSeek Harness (DSH)** autonomous coding agents and Web GUI sessions operating in this repository.

---

## 🎯 Primary Directives & Workflow Loop

We follow the strict **AI-Native SDLC** lifecycle:
1. **Never write non-trivial code in `src/` without an approved `plan.md`** (located under `docs/plans/` or `plans/`).
2. **Ground all plans in validated specs**: All planning traces back to `docs/specs/` (with Gherkin acceptance criteria) and `docs/intent/`.
3. **Strict Test-Driven Development (TDD)**:
   - Red: Write a failing interface or reproduction test in `tests/`.
   - Green: Implement minimal code in `src/` to make the test pass.
   - Refactor: Clean up code while keeping tests green.
   - Never weaken or bypass failing tests.
4. **Single-Command Verification**: Execute `make verify` before declaring any task complete. It must exit 0 with 0 warnings.
5. **Project-Local Environment Isolation**: All tool runs, python environments, and caches must stay strictly within the workspace root (`UV_CACHE_DIR="${ROOT_DIR}/.uv_cache"`). Never touch external user environments or `~/.cache`.
6. **Branch-First Development**: Always create a feature branch (`git checkout -b feat/NNN-title`) from `main` before editing. Direct edits on `main` are strictly forbidden.
7. **Zero Anti-Shortcuts**: No `TODO: implement later`, placeholder functions, or fake mock stubs in production paths. Every execution step must be fully implemented and covered by automated tests.

## 🛠️ Essential Commands in DSH

| Action | Command | DSH Execution & Purpose |
| :--- | :--- | :--- |
| **Verify All** | `make verify` | Runs `scripts/verify.sh` (lint, format, tests, artifact checks). Must exit 0. |
| **Run Tests** | `make test` | Executes unit and integration test suite via project-local UV. |
| **Lint & Syntax** | `make lint` | Validates bash syntax, python AST, and artifact linkages. |
| **Format Code** | `make format` | Automatically formats codebase using project-local ruff. |
| **PR Review Audit** | `make review-pr` | Runs autonomous multi-pass review agent on branch diff. |
| **New Intent** | `make new-intent TITLE="..."` | Scaffolds a new Stage 1 intent artifact in `docs/intent/`. |

## ⚡ DSH Native Tools & Multi-Agent Mapping

DeepSeek Harness provides first-class primitives that map directly to the 6 SDLC stages:

### 1. Skills Subsystem (`.agents/skills/`)
DSH automatically scans `.agents/skills/` (and `.dsh/skills/`) using `dsh-skill-filesystem`. Available skills include:
- `intent-capture`: Conduct the Socratic "Grill Loop" to formulate `docs/intent/NNN-title.md`.
- `spec-architect`: Transform approved intent into Gherkin-compliant `docs/specs/NNN-title.md`.
- `secure-api-design`: Apply API security and schema validation patterns.
- `adversarial-review`: Multi-perspective 3-skeptic review on specs, plans, and diffs.
- `verifier-loop`: Execute `make verify` and enforce zero regressions.

Invoke any skill via the native `skill` tool:
```json
{"name": "spec-architect"}
```

### 2. Multi-Agent Delegation (`subagent` & `subagent_fork`)
Delegate isolated tasks to fresh subagents to keep the parent context clean:
- **Architect subagent**: Designs specs and implementation plans without touching production code.
- **Auditor subagent**: Performs adversarial review on branch diffs against `REVIEW.md`.
- **Engineer subagent**: Executes specific TDD micro-steps.

### 3. Multi-Agent Orchestration (`workflow`)
For complex, multi-agent pipelines (e.g. 3-skeptic adversarial spec panels or multi-pass security audits), write a JavaScript workflow script:
```javascript
const [secReview, perfReview, archReview] = await parallel([
  () => agent("Review spec for security vulnerabilities and injection risks: " + specPath),
  () => agent("Review spec for scalability, latency, and resource constraints: " + specPath),
  () => agent("Review spec for architectural alignment and interface cleanliness: " + specPath)
]);
return { secReview, perfReview, archReview };
```

### 4. Progress & Continuation Tracking
- Use `todo_write` to track micro-stepped execution groups in-session.
- Use `create_goal` / `get_goal` / `update_goal` for multi-round autonomous goals.

## 📁 Repository Organization & Artifact Chain

- `docs/intent/`: Originator problem statement and constraints (`NNN-title.md`).
- `docs/specs/`: Gherkin acceptance criteria (`Given / When / Then`) and API contracts.
- `docs/plans/`: Micro-stepped TDD execution groups and `00-ROADMAP.md`.
- `docs/reviews/`: Automated PR review reports generated by `make review-pr`.
- `.agents/skills/`: Open agent skills auto-discovered by DSH.
- `.claude/commands/`: Claude Code slash commands.
- `.gemini/`: Google Antigravity configuration.
