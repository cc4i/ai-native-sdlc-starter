# Stage 2: Technical Specifications (`specs/`)

This directory houses all Stage 2 technical design and requirements specifications.

## 🎯 Rules
1. **Direct Linkage**: Every spec must link directly to an approved `intent/NNN-title.md` file.
2. **Gherkin Acceptance Criteria**: Every capability must define unambiguous `Given / When / Then` testable scenarios.
3. **Institutional Skill Application**: Specs must apply corporate security, brand, and UX skills during generation.
4. **Adversarial Spec Validation**: Run the `spec-validator` subagent (3-skeptic majority review) to detect ambiguities and holes before writing plans.

## 📄 File Naming Convention
- `NNN-feature-name.md` (e.g., `001-claims-status-self-service.md`)
