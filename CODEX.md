# OpenAI Codex Directives (CODEX.md)

This file provides system instructions, conventions, and operational workflows for **OpenAI Codex** and OpenAI-powered coding agents in this repository.

---

## 🎯 Primary Workflow & Lifecycle Rules

Follow the strict **AI-Native SDLC** lifecycle:
1. **Spec & Plan First**: Never generate non-trivial code in `src/` without an approved `plan.md` in `docs/plans/` grounded in `docs/specs/` and `docs/intent/`.
2. **Strict Test-Driven Development (TDD)**:
   - Red: Write a failing test in `tests/` asserting the required interface or reproducing the bug.
   - Green: Write the minimal code to satisfy the test.
   - Refactor: Clean up code while keeping tests green.
   - Never weaken or bypass failing tests.
3. **Verification**: Always execute `make verify` before declaring any task complete. It must exit 0.
4. **No Placeholders**: Never output stub implementations (`pass`, `raise NotImplementedError`, `// TODO`). Every method must be fully functional.
5. **Branch-First Development**: Always create a feature branch (`git checkout -b feat/NNN-title`) before modifying any code. Direct edits and commits on `main` are strictly forbidden.

---

## 🛠️ Essential Commands

- **Full Verification**: `make verify` (runs linter, code format checks, unit tests)
- **Unit Tests**: `make test`
- **Linting**: `make lint`
- **Formatting**: `make format`
- **Review Diff**: `make review-pr`

---

## 📁 Repository Organization

- `src/`: Core application logic and agents.
- `scripts/`: Verification scripts, git hooks, and release tools.
- `tests/`: Automated unit and integration tests.
- `docs/intent/`: Business and user problem statements.
- `docs/specs/`: Gherkin acceptance specifications.
- `docs/plans/`: Technical implementation plans and `00-ROADMAP.md`.
- `docs/reviews/`: Review audits generated by ReviewAgent.
- `REVIEW.md`: Review criteria and governance rules.
